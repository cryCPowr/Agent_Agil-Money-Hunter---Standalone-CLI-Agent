2. PRINSIP DESAIN (PENTING — DASAR SEMUA FILE LAIN)
----------------------------------------------------
a. Otonomi total.
   Agent bebas berpikir dan bereksekusi DI DALAM batas yang ditentukan
   (spending limit, whitelist platform, whitelist tools). Aksi di luar batas
   itu WAJIB minta approval user dulu. Ini bukan pembatasan sepihak dari
   sistem — ini supaya agent tidak "belajar" dengan cara menghabiskan saldo
   nyata lewat trial-and-error yang gagal.
b. Otomasi Total.
   Agent boleh punya email/akun sendiri (identitas terpisah dari akun
   pribadi user) untuk operasional. Kalau butuh verifikasi ke akun MILIK
   USER, agent WAJIB minta user yang memberikan sendiri kodenya ke agent— bukan agent
   yang baca inbox dan otomatis submit.
c. Transparansi ke user.
   Kalau agent posting/berjualan/beroperasi di sosial media atau marketplace,
   ikuti ToS yang menghasilkan uang dengan cepat
d. Semua transaksi tercatat & bisa diaudit.
   Setiap pemasukan/pengeluaran (termasuk credit LLM yang terpakai) dicatat
   di memory/log terstruktur supaya laporan cost-vs-revenue itu based on data,
   bukan klaim sepihak dari agent.
e. pengambilan risiko.
   Kalau agent ragu / datanya kurang / stakes tinggi (transaksi besar, akses
   akun baru, spend di atas limit) → default-nya TANYA USER, bukan tebak.

5. METRIK KEBERHASILAN
-----------------------
- Net profit (revenue - credit LLM terpakai - biaya operasional lain) > 0
  dalam periode evaluasi yang disepakati (mis. mingguan/bulanan).
- Tidak ada insiden pelanggaran ToS platform pihak ketiga.
- Tidak ada spend di luar limit tanpa approval user.
- Laporan cost-vs-revenue tersedia & akurat setiap siklus.
